# AVEN 产品需求文档（PRD）

版本：1.1 · 日期：2026-11-10 · 状态：M0-01 修订契约（未实现）
需求来源：[原始产品与工程规格](../../Origin%20Plan.md)
工程契约：[TDD](../architecture/TDD.md) · [SCHEMA](../database/SCHEMA.md) · [设计系统](../design/DESIGN_SYSTEM.md)

本文定义 AVEN 首个试点版本的产品范围、首条用户旅程和验收口径。本文不把规划、脚手架、开发数据或 Mock 演示视为功能完成。

## 1. 产品定义

2026-11-12 产品交互澄清：用户将 AVEN 定义为以对话为核心、具有社交属性并能够跨不同用户终端建立连接的 AI 产品。主体验类似成熟 AI 聊天工具；发现人、连接、引荐、机会与协作是按需调用的能力，通过插件入口和会话内小组件呈现，不以业务页面目录主导首页。原有明确授权、双方决定、组织边界和撤销规则保留。本文后续的页面清单描述功能覆盖，不要求每项成为主导航；第一版不实现任意第三方代码执行的插件市场。

AVEN 是面向个人与组织的 AI 连接网络。首个试点场景为西安交通大学，围绕科研机会、合作连接与真实活动协调展开。

产品不是传统校园社交软件，也不是无限信息流或招聘网站。它要解决的是：

1. 个人如何让系统理解自己的长期目标、能力与当前需求。
2. 组织如何表达自己的资源、项目与真实需求。
3. 系统如何在明确授权下发现值得建立的人与组织连接。
4. 连接如何转化为真实的交流、合作与活动。

### 1.1 四种基本能力

| 能力 | 说明 | 首个可验收表现 |
|---|---|---|
| 理解个人 | 个人资料、已确认记忆、需求与偏好 | 用户可查看、纠正和删除自己的上下文 |
| 理解组织 | 组织资料、成员、机会与组织上下文 | 组织可发布真实机会并管理成员 |
| 发现连接 | 硬条件过滤、语义召回、可解释排序 | 推荐理由能对应到获授权的真实证据 |
| 转化行动 | 授权、引荐、关系空间、日程与活动 | 双方确认后建立唯一关系空间，撤销后停止访问 |

### 1.2 产品边界

- AI 是贯穿产品的智能基础设施，不是唯一入口。用户可以直接搜索、编辑资料、接受引荐。
- 不做无限信息流。首页只呈现与用户相关的机会、连接和待办。
- 不做没有解释的匹配分数。每条推荐必须能说明使用了哪些获授权信息。
- 不把私人记忆默认用于对外共享。共享必须经过明确的授权预览。
- 不以页面演示代替真实数据、权限和失败路径。

### 1.3 渐进交付与首轮验证

- 首条确定性闭环：组织发布机会、个人确认最小资料、发现、授权引荐、关系空间和撤销。它是受控验证版本，不是完整 MVP；原始 18 项 DoD 保留。
- 个人不必先填写完整履历或进行长对话。先以最少资料浏览，再在申请时补齐必要字段；不以交出私人记忆作为浏览公开机会的条件。
- 首轮验证真实机会供给、组织响应和一次有价值的交流，而不是页面数量。招募时明确试点性质、数据用途、退出方式、举报/删除入口和支持负责人。
- 使用真实用户数据前，记录机会维护人、响应承诺、机会到期处理和删除流程；无足够机会时清楚展示空状态，不制造推荐。
- 完整日程、多主体社交发现和复杂组织分析不进入首条闭环；未开放模块从主要导航隐藏。

## 2. 目标用户

| 角色 | 目标 | 主要痛点 | 首版需要 |
|---|---|---|---|
| 个人用户（本科生、研究生、研究者） | 找到适合的科研机会、合作者、导师或活动 | 信息分散、不知道自己适合什么、害怕隐私泄露 | 个人资料、需求、发现、授权引荐、关系空间 |
| 组织管理员（实验室、课题组、社团、学院） | 发布机会、筛选合适的个人、维护组织资料 | 收到大量不匹配请求、缺少结构化信息 | 组织资料、机会管理、引荐收件箱、成员管理 |
| 组织成员 | 代表组织查看引荐、参与合作 | 权限不清、信息过载 | 组织空间、受控的引荐查看与响应 |
| 平台运营/审核 | 处理校园认证、举报与数据删除 | 缺少审计与边界 | 审核队列、审计日志、受限管理入口 |

首版不面向校外企业、付费招聘方和公开社交关系链。

## 3. 核心原则

| 原则 | 产品含义 | 工程约束 |
|---|---|---|
| AI First, Not Chat First | 每个核心任务都可以直接操作，也可以交给 AI | AI 调用同一套业务服务，不另建一套逻辑 |
| Context Before Conversation | 回答基于用户确认过的上下文 | 只使用已确认、未过期、允许该用途的信息 |
| Network Before Feed | 首页呈现相关的人、项目、机会和行动 | 不做无限滚动和泛化推荐 |
| Minimal Interface, Deep Capability | 界面简洁，复杂过程在后台 | 明确展示 AI 在做什么、为什么推荐、需要确认什么 |
| Human-Controlled Network | 共享、关系建立和高影响操作必须授权 | 默认拒绝、服务端复核、可撤销、可审计 |

## 4. 首条用户旅程

首条旅程是首个业务验收目标，不等同于完整 MVP。

### 4.1 主流程

| 步骤 | 操作者 | 动作 | 系统行为 | 成功结果 | 失败/边界 |
|---|---|---|---|---|---|
| 1 | 组织管理员 | 创建组织并发布科研机会 | 校验组织成员与管理员权限；保存机会、要求、截止时间和可见范围 | 机会处于 `open`，可被授权范围内的人发现 | 非管理员被拒绝；草稿不参与匹配；过期机会不参与新推荐 |
| 2 | 个人 | 建立账号，确认兴趣、技能、项目经历，创建寻找需求 | 保存已确认资料与需求版本；记录来源、敏感度和用途 | 个人上下文可用于匹配 | 未确认的 AI 候选不进入匹配；私人字段不进入公开响应 |
| 3 | 个人 | 查看推荐机会与推荐理由 | 按学校、领域、阶段、期限、意愿、屏蔽关系过滤；返回证据 | 候选人看到可验证的推荐原因 | 无合适结果时明确展示空状态，不编造匹配 |
| 4 | 个人 | 打开机会详情，选择本次共享的资料、接收方、用途和有效期 | 生成授权预览；列出将披露与不披露的字段 | 用户看到明确的共享清单 | 授权不能由模型扩大；过期或撤销的授权不能发送 |
| 5 | 个人 | 确认发送引荐 | 创建引荐与授权；记录双方独立决定 | 组织收件箱出现待处理引荐 | 重复点击不产生重复引荐；内容变化要求重新预览 |
| 6 | 组织管理员/获授权成员 | 查看获授权资料，接受、拒绝或请求补充 | 接受时在事务内复核机会、成员权限、双方决定、授权和人数 | 只建一个关系；有独立关系用途授权才绑定快照，否则共享上下文为空 | 并发接受只产生一个空间；拒绝/撤回/过期有明确结果 |
| 7 | 个人 | 撤销指定授权 | 立即拒绝相应内容的新读取；清理缓存、索引和异步任务中的残留访问 | 受影响内容不再通过系统返回 | 其他独立有效授权不受影响；无法收回接收者系统外保存的副本 |

### 4.2 首条旅程验收

- 两个真实账号分别代表个人与组织，使用真实数据库完成主线。
- 每条推荐理由都能对应到允许使用的证据，而不是模型自由生成。
- 只有双方接受才建立关系；重复接受、并发接受、重复请求只产生一个关系空间。
- 拒绝、撤回、过期、机会关闭、授权失效都有明确的用户可见结果。
- 撤销后，关系空间、缓存、检索和异步任务都不能继续返回相应内容。
- 越权读取、跨组织访问、伪造主体、被移除成员访问均被拒绝并留下审计元数据。

## 5. 功能范围

### 5.1 身份、校园与组织

- 邮箱 + 密码注册、登录、登出、邮箱验证、密码找回。
- 会话管理：查看活跃会话、撤销单个会话；修改/重置密码后撤销全部会话，要求重新登录。
- Principal 统一主体：个人、组织、项目、关系空间均有 Principal ID；主体类型与子表记录一致。
- 校园身份：注册或选择学校不等于通过校园认证；认证状态独立记录。
- 组织：创建、资料编辑、邀请/接受、管理员/成员角色、移除/离开、最后一名管理员保护。
- 组织操作主体：组织管理员代表组织操作；普通成员默认不能代表组织接受引荐。
- 开发身份：只允许在显式开发环境启用，不能成为生产鉴权回退。

### 5.2 个人上下文与记忆

- 手工维护兴趣、技能、项目、目标、偏好、教育经历。
- 每条记忆包含来源、所有者、敏感度、可见性、确认状态、有效期和版本。
- AI 提取只生成待确认候选；用户接受、修改或拒绝后才进入相应用途。
- 用户可编辑、失效、删除记忆；删除后清理索引和关联授权影响。
- 私人记忆不会因为参与对话自动对外共享。
- 用户可查看“哪些信息仅本人可见、哪些参与匹配、哪些已共享、哪些授权仍有效”。

### 5.3 需求与机会

- 个人创建寻找需求：目标、领域、阶段、时间投入、地点/远程偏好、截止时间。
- 组织创建机会：标题、简介、要求、领域、阶段、人数、时间投入、负责人、截止时间、可见范围。
- 机会生命周期：草稿、开放、暂停、关闭、到期。
- 编辑机会产生新版本；接受引荐时复核机会仍可用。
- 普通成员不能越权发布；被移除成员不能继续操作已生成的草稿。

### 5.4 匹配

- 第一版以确定性过滤为基线：学校、领域、阶段、期限、意愿、屏蔽关系、机会状态。
- 语义召回使用 pgvector，但只检索有权使用的候选集合。
- 排序使用可解释特征；每条结果保存算法版本、计算时间、意图与来源版本、特征评分、过滤原因和推荐理由。推荐候选仅本人及受限匹配任务可读，组织不能提前读取候选或私人证据。
- LLM 只生成自然语言解释，不决定全部匹配结果。
- 无合适结果时展示空状态，不伪造匹配。

### 5.5 授权与引荐

- 授权包含：授权主体、接收主体、数据范围、用途、有效期、版本、撤销状态。
- 发送前展示明确的共享清单：将披露什么、对方是谁、用途是什么、何时过期。
- 组织可接受、拒绝或请求补充资料；补充资料走新的预览和授权。
- 推荐候选与正式引荐分开保存；直接申请也可创建引荐，不要求先有推荐候选。终态后重发创建新的引荐，不覆盖旧决定。
- 双方决定独立记录；发送表示个人对本次版本接受，组织接受是另一方决定；引荐状态与授权状态分开。
- 接受时在事务内重新校验权限、机会状态、授权、人数和重复关系。
- 支持撤回、过期、机会关闭和授权失效的明确行为。

### 5.6 关系空间

- 双方接受后建立唯一关系空间；一个引荐最多一个关系。
- 关系空间包含 Overview、成员、共同目标、会话和共享上下文。
- 共享上下文引用经过授权的不可变快照，并绑定原授权、来源版本和该关系对应的引荐。
- 引荐用途不自动升级为关系用途：用户可在发送时分别确认两种授权，或关系建立后另行授权。未确认关系用途时先建立空共享上下文，不复制引荐资料、不默认延长授权。
- 组织接收的私人快照仅当前 owner/admin/`can_represent` 成员可读；其他组织成员可见空间元数据，不自动获得私人资料。
- 读取共享上下文时仍检查接收主体、用途、过期和撤销状态。
- 关系关闭不自动赋予另一方继续访问全部历史数据的权利。

### 5.7 AI

- 个人 AI 与组织 AI 使用同一套 Provider 抽象和工作流运行时。
- 默认使用 Mock Provider，开发时明确标识；真实 Provider 通过配置接入。
- AI 可以提出草稿、检索、解释和准备行动，但正式发布、发送引荐和共享资料必须经过后端确认流程。
- 行动确认绑定草稿内容版本、有效期和一次性执行标识；执行时重新鉴权。
- 流式输出区分文字生成、工具执行、等待确认、异步任务和失败状态。
- 工具必须有参数 Schema、权限要求、超时、重试、幂等和审计记录；Agent 不能直接访问数据库。

### 5.8 日程与活动（M6）

- 个人日程与忙闲块；统一 UTC 存储并保留时区。
- 仅共享获授权的忙闲，不暴露日程标题和私人细节。
- 确定性计算共同可用时间；覆盖无交集、跨天和夏令时。
- 活动状态：草稿、提案、等待确认、成立、取消、结束；参与人响应独立记录。
- AI 提取约束，业务求解器计算候选；不自动修改所有人的外部日历。

### 5.9 通知

- 站内通知为首版必需；移动推送在 M6 接入。
- 通过 Outbox + 队列投递，支持幂等、失败重试、去重和死信处理。
- 用户可配置通知偏好；通知失败不损坏业务状态。

### 5.10 运营与审计

- 审计只保存必要的操作主体、资源、决定、版本和结果，不保存私人对话正文、模型上下文或密钥。
- 支持举报、数据删除和校园认证审核的最小流程。
- 关键权限和隐私事件可追踪；审计记录不可由普通业务角色修改。

## 6. 非目标

首版明确不做：

- 无限信息流、公开动态墙、泛社交推荐。
- 支付、订阅、招聘佣金和广告。
- 自由协商的多 Agent 系统。
- 复杂场地优化、多人多资源排程和交通成本优化。
- 多校园运营和高度定制的组织报表。
- 以 WebView 包装 Web 的“伪原生”移动端。
- 用 Mock 输出证明 AI 能力已完成。
- 在首条闭环稳定前接入真实模型、Android 全链路或日程模块。

## 7. 可见性与授权

### 7.1 可见性是用途，不是等级

原规格名称保留为 UI 策略预设，不作为单值数据库权限枚举。每个可披露字段分别配置以下维度，缺失策略默认仅本人、关闭全部用途：

| 维度 | 值 | 含义 |
|---|---|---|
| 展示范围 `display_audience` | `owner` / `campus` / `public` | 原始字段的展示受众；校园范围要求有效认证，个人原始记忆仍不直接对外读取 |
| 发现 `discoverable` | 布尔，默认 false | 是否进入发现结果；启用时展示范围不能是 owner，只输出允许的字段投影 |
| 处理用途 `allowed_uses` | `self_ai` / `matching` / `sharing` 的独立集合，默认空 | 允许用于本人 AI、匹配或准备共享；不互相推导，不因公开而默认发送给 Provider |
| 对外授权 ConsentGrant | 接收方、用途、业务对象、字段、版本、期限 | 实际引荐/关系披露的必要条件；`sharing` 不等于已经授权 |

例如技能可以仅允许 `matching`，也可以允许校园发现并参与匹配；关系空间只通过 `relationship_context` 授权快照读取。UI 必须允许查看组合与影响，不能用“更公开”的单一滑块代替。

`private` 预设关闭对外展示与处理用途；`match_only` 仅开启 matching；`relationship_shared` 仅准备 sharing 并另行授权。用户为本人 AI 选择已有私人字段时须明确开启 self_ai 用途，不自动开启任何对外用途；用户本次直接输入仍按当前请求的最小用途处理。

### 7.2 字段级示例

| 字段 | 本人 | 发现 | 匹配 | 引荐预览 | 关系空间 | 公开 |
|---|---|---|---|---|---|---|
| 显示名 | ✓ | 按字段 | 按用途 | 快照 | 快照 | 按资料设置 |
| 校园/学院 | ✓ | 按字段 | 按用途 | 快照 | 快照 | 按资料设置 |
| 兴趣/技能 | ✓ | 按字段 | 按用途 | 快照 | 快照 | — |
| 项目摘要 | ✓ | 按字段 | 按用途 | 快照 | 快照 | 按项目设置 |
| 私人记忆正文 | ✓ | — | 仅明确允许的派生字段 | 仅选中字段 | 仅快照 | — |
| 邮箱 | ✓ | — | — | 仅明确选择 | 仅明确选择 | — |
| 日历标题 | ✓ | — | — | — | — | — |
| 忙闲块 | ✓ | — | 仅授权用途 | — | 仅授权用途 | — |

“快照”表示只读取授权时保存的字段值，不直接连接原始私人记录。

### 7.3 授权规则

- 授权主体与接收主体必须明确；接收主体可以是个人或组织。
- 授权必须绑定用途、业务对象、字段集合、来源版本、有效期和版本号；不能将另一引荐、关系或活动的授权混用。
- 授权范围变更产生新版本，不能原地扩大已确认内容。
- 撤销一个授权不影响其他独立有效授权。
- 读取共享快照仍检查接收主体、用途、过期和撤销状态。
- 来源被删除、失效或收紧字段策略时，依赖它的授权项同步失效；拒绝、撤回、过期引荐同时撤销该引荐授权，不继续披露。
- 普通内容编辑不自动更新旧快照；来源删除、失效或收紧用途时，相关授权项必须在同一事务失效，新读取不能等待后台清理。UI 提示旧版本仍曾被共享，提供撤销与重新授权。
- 撤销提交后，在主库授权检查点开始的新读取必须拒绝；已通过检查并发出的在途响应无法保证收回。流式与后台任务在后续输出/副作用前复核并停止，客户端清除可控缓存。不能收回已送达或系统外保存的副本。

## 8. 关键状态与失败行为

| 对象 | 状态 | 用户可见行为 |
|---|---|---|
| 记忆 | 待确认、已确认、已拒绝、已失效、已删除 | 待确认不参与匹配；删除后不再展示，关联快照失效 |
| 机会 | 草稿、开放、暂停、关闭、到期 | 草稿和暂停不参与新推荐；关闭/到期不能接受新引荐 |
| 推荐候选 | 有效、失效、已忽略 | 仅本人可见；重算不改变已发送引荐 |
| 引荐 | 已发送、待补充、已接受、已拒绝、已撤回、已过期 | 每个状态有明确说明和可用操作；过期不能接受；重发保留历史 |
| 授权 | 有效、已撤销、已过期 | 撤销/过期后读取被拒绝；其他授权不受影响 |
| 关系 | 有效、已关闭 | 关闭后保留必要历史，但不再新增共享 |
| 行动 | 草稿、等待确认、执行中、成功、失败、取消、过期 | 草稿变化要求重新预览；重复确认不重复执行 |
| 活动 | 草稿、候选提案、等待确认、已成立、已取消、已结束 | 确认绑定提案版本；候选变化使旧确认失效 |

失败必须区分：权限拒绝、业务冲突、版本冲突、授权撤销/过期、机会关闭、限流、Provider 超时、网络断开。不能把所有错误显示成“出错了”。

## 10. 产品指标

不以 DAU 为唯一指标。首版关注：

| 类别 | 指标 | 口径 |
|---|---|---|
| 个人智能 | 初始化完成率 | 完成至少一项已确认资料的用户 / 注册用户 |
| 个人智能 | 记忆确认率 | 已确认候选 / 生成的候选 |
| 个人智能 | 记忆修改率 | 被用户修改后确认的候选 / 已确认候选 |
| 网络 | 机会发现数 | 有效搜索或推荐产生的机会查看数 |
| 网络 | 引荐接受率 | 同一发送批次中组织接受的引荐 / 已发送引荐，注明观察窗口 |
| 网络 | 关系建立成功率（工程） | 已成功建立唯一关系的引荐 / 组织已接受引荐；发送已代表个人接受，不作为独立双向转化率 |
| 网络 | 交流启动率（代理指标） | 7 天内有双方消息元数据或活动确认的关系 / 已满 7 天观察期的关系，不读取正文 |
| 网络 | 有效连接反馈率 | 14 天内双方自愿反馈有价值的关系 / 已满 14 天观察期的关系；另报反馈覆盖率，不以消息数冒充实际交流完成 |
| 组织 | 活跃组织数 | 30 天内有发布或响应的组织 |
| 组织 | 响应时间 | 引荐发送到组织首次决定的中位时长 |
| 生活 | 活动确认率 | 确认活动 / 创建活动 |
| 信任 | 授权撤销率 | 撤销授权 / 创建授权 |
| 信任 | 隐私事件 | 越权访问、错误共享、投诉数量 |

产品分析不采集私人对话正文、模型上下文或密钥。所有指标按去重实体 ID、发送批次、观察窗口定义分母，样本不足时报告样本与限制，不承诺未验证的增长目标。试点前登记机会供给、首次有效机会耗时、组织响应时长和用户自愿反馈的验收目标；没有真实数据前不声称产品有效。

## 12. 开放问题

以下问题不阻塞 M0-01，但必须在对应阶段前关闭：

1. 校园认证采用哪种证据：学校邮箱域名、学生证人工审核，还是两者结合？首版建议“邮箱域名作为信号 + 人工审核作为认证”，不把域名自动等同于官方认证。
2. 生产环境部署在哪里：M0 确认候选地域、预算与网络，真实数据试点前确认数据位置、适用备案及个人信息处理要求，M7 复验；不能到上线前才首次调查。
3. 邮件发送服务：开发环境用邮件捕获，生产用哪个国内可用的服务？
4. 真实 AI Provider：首个接入哪个 OpenAI-compatible 服务？需要确认密钥管理、数据出境和限流。
5. 文件存储：首版是否需要上传简历/材料？如果需要，使用 S3 兼容存储（本地 MinIO）并做签名链接和下载权限。
6. 数据保留期限：会话、审计、已删除记忆、授权事件分别保留多久？
7. 组织认证：谁审核、需要什么材料、认证状态如何展示？
8. 组织成员代表权按 TDD 的 owner/admin/`can_represent` 执行；代表权撤销立即影响新读取和未执行草稿，验证在 M2/M5 完成。
9. iOS：是否在 M7 前投入？当前计划保留技术路径，不作为首版必要验收项。
10. 举报与内容治理：首版最小流程是什么，谁处理，响应时限如何？

## 13. 术语表

| 术语 | 含义 |
|---|---|
| Principal | 统一主体标识，可代表个人、组织、项目或关系空间 |
| MemoryItem | 经过筛选和确认的结构化个人上下文，不是完整对话记录 |
| Intent | 个人当前寻找合作、机会或资源的需求 |
| Opportunity | 组织发布的真实机会 |
| MatchCandidate | 本人可见的推荐候选，不是已发送引荐 |
| Referral | 正式引荐，独立于候选与算法重算，具有自己的状态与历史 |
| ReferralDecision | 个人或组织对引荐的独立决定，替代基线 MatchDecision 名称 |
| ConsentGrant | 授权主体向接收主体授予的用途、范围和期限 |
| SharedContextItem | 关系空间中绑定授权和来源版本的共享快照 |
| Relationship | 双方接受后建立的关系空间 |
| OutboxEvent | 与业务写入同事务保存、用于可靠投递的事件 |
| Mock Provider | 开发用确定性 AI Provider，必须明确标识 |
