# ADR-007：授权边界与可靠读取

- 状态：已接受（仅契约；M0-05/M2/M5 实现与验证）
- 日期：2026-11-10
- 取代：[ADR-004](0004-data-authorization.md)；补充 ADR-002 的认证数据库边界
- 相关：[PRD](../../product/PRD.md) · [TDD](../TDD.md) · [SCHEMA](../../database/SCHEMA.md)

## 背景

M0-01 的安全原则正确，但单值 visibility 无法表达独立用途，推荐候选与引荐共用状态会提前暴露信息，RLS 示例的全表授权、认证启动和撤销承诺也未闭合。当前没有应用代码或迁移，可以在实施前修订契约，不需要兼容尚未发布的接口。

## 决策

1. **展示、处理与披露分离**：字段策略使用 `display_audience`、`discoverable`、`allowed_uses`；所有用途默认关闭。`sharing` 仅允许准备共享，实际披露仍需绑定接收方、用途、业务对象、来源版本和期限的 ConsentGrant。旧 visibility 名称只作为 UI 预设，不存为权限等级。
2. **候选不等于引荐**：`match_candidates` 仅本人/受限匹配任务可见；`referrals` 保存正式发送、补充、决定和历史。组织只读取已发送引荐的元数据及当前有效授权快照，不读取原始候选证据。
3. **用途不自动升级**：`referral` 授权不能直接变成 `relationship_context` 授权。发送时可分别预览并确认两种用途，也可先建立空上下文的关系，再独立授权；不得默认延长有效期。
4. **快照值单一来源**：值保存在不可变的 `consent_grant_items`；共享上下文通过复合外键引用它。读取同时核对参与者、接收主体代表权、用途、业务绑定、grant/item 状态、来源失效状态和期限。可撤销读取不使用只读副本或最终一致的授权缓存。
5. **最小数据库权限**：`aven_app`、`aven_worker`、`aven_auth` 分离，均无 DDL、无 BYPASSRLS；不授予全 schema DML。认证池只暴露受限函数；密码/token 哈希不能被普通业务池直接读取。函数所有者 `aven_function_owner` 为 NOLOGIN、非表所有者、NOBYPASSRLS，仅有逐表所需权限和显式 RLS 策略。
6. **安全定义函数不隐式绕过 RLS**：固定可信 `search_path`，`pg_temp` 最后，业务对象使用 schema 限定；撤销 PUBLIC EXECUTE；运行角色不能成为函数所有者。成员辅助函数避免策略递归。注册、登录、重置、会话与邀请流程逐项定义，不靠伪造已登录身份启动。
7. **普通写入的事件可达**：业务事务通过受控追加函数写 Audit/Outbox，函数验证资源与事件类型并从可信上下文派生 actor；普通请求不设置 worker/admin 标志来绕过策略。拒绝事件在失败事务外保存脱敏元数据。
8. **撤销的精确定义**：撤销提交后，在主库授权检查点开始的新读取必须拒绝；行锁只排序数据库内的读取与撤销，不保证截断已在途的网络字节。流式输出分批复核并在失效时停止，客户端清除可控缓存；已送达或系统外副本无法收回。
9. **RLS 的威胁边界明确**：事务上下文由可信服务写入，用于防遗漏过滤与连接池串身份；同一数据库连接可设置的 GUC 不是防任意 SQL 执行的独立身份凭据。角色隔离、参数化查询和应用授权仍然必需，`is_worker` 不得只取决于可写 GUC。

## 备选方案

- 保留单值 visibility 并增加隐含等级：无法表达独立用途，拒绝。
- 组织直接读取推荐候选后由前端隐藏字段：违背披露时机，拒绝。
- 用超级用户或公共 BYPASSRLS 连接解决认证：扩大权限，拒绝。
- 只删除缓存声明撤销完成：无法阻止其他读取入口，拒绝。

## 后果

需要调整尚未实施的表、接口与测试契约；不新增应用功能，不宣称 RLS 或授权已经验证。受控函数及角色比单一应用账号更复杂，但权限复杂度集中在数据库包，不能散落到控制器。当前只实现首条个人到组织的引荐，其他主体组合随业务另行验证。

## 验证门

- [ ] 普通池无法读取哈希、修改认证凭据、切换到其他运行/函数角色；认证池无法读取记忆。
- [ ] 无身份注册/登录/重置、本人会话撤销和普通业务追加事件均可完成；函数在 FORCE RLS 下可用且无递归。
- [ ] 未认证校园成员、其他校园、组织低权限成员均不能通过策略读到受限内容。
- [ ] 未发送候选不可被组织读取；终态重发保留独立历史。
- [ ] 用途升级、错配 grant/item、来源删除、过期、撤销与幂等重放不绕过授权。
- [ ] 覆盖撤销先提交、读取先取锁、在途流、客户端缓存和任务重试，分别记录保证与限制。
