# ADR-018：Web 与 Android 个人工作区开发

- 日期：2026-11-13
- 状态：已接受（实施授权；验收须另有证据）
- 部分取代 ADR-017 的 Android 暂缓范围及 ADR-008 对本轮个人界面的编码顺序限制；不改写历史决策。

## 授权与范围

用户明确要求“进行下一轮，把 web 和 Android 进行全面梳理和开发，将其完成开发”。本轮据此开始 Android 原生个人工作区，补齐 Web 的账号设置、密码恢复、会话管理与运行历史入口。复用现有共享客户端、服务端权限和设计令牌，不采用 WebView。

Android 范围：注册、登录、邮箱验证与密码恢复；安全存储移动会话令牌；Mock Agent 流式回复、取消与手动恢复；记忆创建、复核、编辑撤回；个人邀请预览/发送/决定/撤销、消息与分页；站内通知及偏好；连接器 Mock 表单和声明式卡片；账号资料和会话管理。

## 安全与保留

1. 移动使用 Bearer 且不携带 Cookie；令牌仅保存在 Android Keystore 支持的 SecureStore，不持久化私人正文。后台立即卸载私人视图、终止读取，恢复前重新鉴权；401 清除令牌。
2. API 地址固定由构建环境指定；生产仅 HTTPS。明确区分 Android 模拟器、真机与开发机地址。
3. 历史入口只返回本人个人 run 的标识、状态、时间和 Provider 等元数据，不返回输入/输出正文。以键集游标分页；重新读取仍走现有逐次来源复核与 24 小时 SSE 保留窗。历史到期不能重新生成答案冒充恢复。
4. 写入不自动重试；Agent/邀请/消息未知结果保留原请求标识，用户手动核对。版本冲突重新读取。共享用途默认关闭，预览和发送分开，撤销/删除二次确认。
5. 默认 Mock；不启用真实 Provider、第三方 OAuth、真实 MCP 或生产试点。真实外部服务、移动推送、正式双端设计评审与发布验收仍需独立证据。

## Android 构建环境

用户明确指定通过 GitHub Actions 生成 APK，不在本机进行原生编译。`.github/workflows/android-apk.yml` 执行 CNG prebuild 与 Gradle release APK，使用生成的开发签名，仅供内部安装；产物包含 JS，无需 Metro。API origin 使用工作流输入或仓库变量 `EXPO_PUBLIC_API_URL`，仅允许 HTTPS origin；未配置时只显示配置引导。无云端生产签名或商店发布授权。远端构建与真机验收分别记录。

## 完成判据

按实际工程检查、真实 HTTP/数据库与 Web 回归、Android 原生构建和设备操作分别记账。JS 导出不替代 APK；无法执行的设备/发布检查明确记录为未验证。全量 MVP 的其他工作包不随本授权自动 DONE。
