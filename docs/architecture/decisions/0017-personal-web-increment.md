# ADR-017：用户授权的个人 Web 限定接入

- 日期：2026-11-12
- 状态：已接受（限定个人 Web）；验证见 WEB_PERSONAL.md
- 部分取代 ADR-008 中对应页面必须等待整包双端评审后编码的顺序要求；其余验收、安全、原生与试点门不变。

## 背景与授权

用户在 v0.4 图片对齐、正圆角色及动效迭代后，明确要求“好的，开始进行下一阶段开发”。上轮已说明下一阶段为登录、对话、个人连接/消息和通知的 Web 接入。本轮据此开始限定范围实现，不将这次实施授权代记为 M1-07 全部页面或正式双端设计验收通过。

## 决策

1. 个人 Web 沿用 v0.4 浅色气泡、圆角、胶囊输入区与正圆角色。范围为邮箱注册/登录/退出、真实会话校验、Mock Agent 请求/SSE/取消/断流恢复、本人手工记忆、用途预览后的个人邀请、已有连接消息和站内通知。复用现有 API、共享客户端和 Zod 契约。
2. 邀请只通过对方主动分享的连接码定位：`aven:<user UUID>` 是用户可主动复制的邀请地址标识，不是认证令牌，也不授予读取资料的权限。发送前列出完整接收码、实际字段快照、用途及期限；不伪造姓名、发现结果或模型推荐。
3. 不接入真实 Provider、第三方 OAuth、远程插件或 Android；0039 日历迁移不属于这条 Web 主线，不为前端接入修改数据库。
4. 浏览器经同源 API 重写；HttpOnly Cookie 认证，写请求逐次读取 CSRF Cookie；无 token/正文 localStorage、自动写重试或鉴权回退。会话过期、身份切换、离线/页面恢复先隐藏私人视图，再重新验证。断流恢复只订阅既有 run；结果未知的创建请求使用原幂等键手动核对。
5. 工程诊断迁至 `/diagnostics`。不展示虚构的历史会话；当前会话只有当前页面内存视图，刷新后不自动重放正文或发送行为。
6. M1-07 整体保持 REVIEW；M1-02–06/M3-07 按实际交付范围标为部分完成，不能据此关闭组织端、原生端、正式设计与产品旅程验收。

## 验证

真实 Cookie/CSRF 登录、Mock Worker→SSE→浏览器、独立账号邀请/接受/消息、退出与 401 清除、断流/重放/取消、输入校验、无正文缓存、手机与键盘检查。按实际运行结果更新 README 与开发计划，不以页面截图代替业务检查。

实际结果见 [WEB-01 交付记录](../../development/WEB_PERSONAL.md)：真实业务复验 18 项、恢复检查 7 项、网页 E2E 12 项与 299 项单测通过；Expo 依赖兼容检查仍失败。该结果不扩大本 ADR 的授权范围。
