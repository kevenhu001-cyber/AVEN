# ADR-006：AI Provider 接入

- 状态：已接受（M3 验证）
- 日期：2026-11-10
- 相关：[TDD](../TDD.md) · [PRD](../../product/PRD.md)

## 背景

首版需要个人 AI 和组织 AI，但不能让开发依赖真实模型密钥，也不能把某家供应商写死。首个试点在中国校园网络，模型可用性、数据出境、成本和限流都需要验证。Mock 输出不能证明智能能力已完成。

## 决策

1. 定义统一 `AIProvider` 接口：文本生成、结构化输出、流式输出、Embedding。
2. 默认使用 **MockProvider**：确定性输出、固定样例、UI 明确标识“开发模式：Mock AI”；不需要真实密钥。
3. 提供 **OpenAI-compatible Provider**：base URL、API key、model、timeout 可配置；不把供应商逻辑写进业务模块。
4. 模型按任务路由（意图提取、分类、记忆整理、解释、Embedding）；具体模型由配置决定。
5. 真实 Provider 接入后单独验证成功、限流、超时、错误、取消和数据范围；Mock 结果不作为完成证据。
6. 数据最小化：只发送当前用途允许的字段；不发送完整私人记忆或对话历史；不把私人正文写入日志/分析。
7. 所有工具必须有 Zod 参数、权限要求、超时、重试、幂等和审计；Agent 不能直接访问数据库。
8. 高影响行动走草稿 → 预览 → 用户确认 → 执行；确认绑定草稿版本、有效期和一次性标识。
9. Provider 故障时明确降级/报错，不静默切换模型或伪造结果。

## 备选方案

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| 直接使用某家 SDK | 接入快 | 供应商锁定，切换成本高 | 不采用 |
| 只做 Mock | 无外部依赖 | 无法验证真实能力 | 仅开发基线 |
| 多 Provider 全家桶 | 灵活 | 首版过度，测试矩阵大 | 逐步增加 |
| 统一接口 + Mock + OpenAI-compatible | 可替换、可开发 | 需要适配层和评估 | 采用 |

## 后果

- 需要 `packages/ai-core`、Provider 配置、Mock 样例和评估集。
- 真实 Provider 的密钥、数据位置、保留策略和限流在上线前确认。
- 流式输出需要 SSE 契约、取消和恢复；不能把工具状态混成文字状态。
- 模型输出必须经过结构化校验和权限复核；不能直接执行模型生成的 SQL/HTTP。
- 评估记录模型、配置、失败案例和来源支持情况。

## 验证

- [x] Mock 模式无需密钥即可完成开发流程，`metadata.mock=true` 明示（M3-04）。
- [ ] OpenAI-compatible Provider 成功、限流、超时、错误路径（适配器已用假 fetch 验证，真实网络未接入）。
- [x] 工具参数伪造、权限、数据用途、超时、重试与审计测试（M3-04）。
- [ ] 行动确认重复执行不产生重复副作用（M3-06）。
- [ ] 流式取消、断线恢复和终止事件（M3-05）。
- [x] 日志/分析不含私人正文、提示词或密钥（M3-04 审计仅元数据；未接入运行时日志）。
