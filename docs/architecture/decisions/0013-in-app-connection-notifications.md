# ADR-013：个人连接站内通知与事务回执

- 日期：2026-11-12
- 状态：已接受，本轮实施与验证
- 补充 ADR-005/007/011

个人邀请目前只能由接收方主动查列表发现。本轮在 connection_events AFTER INSERT 触发器追加仅含事件 ID 的 Outbox 和投递记录，与原业务事务同提交；不改写已应用迁移，不补发历史通知。

站内通知仅包含固定类型与业务对象 ID，不复制授权正文或私人身份字段。通知可见性在主库核对当前业务状态、双方状态和接收方；详情继续走当前连接授权。偏好在消费时检查，不将通知开关当作数据披露授权。

以 notification_deliveries 的 event_id 唯一键作为原子消费回执，通知写入与回执同事务；不依赖 Redis jobId 提供 exactly-once。复用 Outbox 派发器，独立 BullMQ 消费者及 pending 对账。数据库重新读取来源事件和接收方，不信任队列携带身份/正文。5 次失败进入 dead；当前平台管理员可按 generation 重排并留审计，旧代数任务不能影响新代数。

新增 notifications、notification_preferences、notification_deliveries、notification_delivery_events；FORCE RLS，用户只读本人当前可见通知，写入仅受控函数。实际 Worker 会话才可消费/记录失败/维护，不能通过 GUC 提权。通知与正文分离，90 天后清除收件箱条目但保留去重回执。

M6-06 分阶段交付：本轮 A1 只覆盖个人连接的站内通知，A2 补活动通知，之后推送/设备与产品 UI。生产调度、指标告警和全系统保留不因本轮视为完成。

验证业务回滚、真实 Redis/BullMQ、重复/并发消费、入队后崩溃/丢任务对账、偏好与当前授权过滤、跨账号/伪造事件、五次失败和管理员重排、旧代数回调、90 天清理不复活，以及空库/升级与已有业务回归。
