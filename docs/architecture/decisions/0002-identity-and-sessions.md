# ADR-002：身份与会话

- 状态：已接受（M2 实现）
- 日期：2026-11-10
- 相关：[TDD](../TDD.md) · [SCHEMA](../../database/SCHEMA.md)

## 背景

首个试点在西安交通大学。身份需要支持 Web 与 Android、会话撤销、密码找回、校园认证状态，并且不能依赖无法保证在中国校园网络稳定访问的海外身份 SaaS。

原规格未选定身份提供方。开发测试身份只能用于显式开发环境，不能成为生产鉴权回退。

## 决策

采用 **自建邮箱 + 密码 + 不透明会话**：

1. 邮箱规范化后唯一；密码使用 Argon2id 哈希。
2. 会话 token 为 32 字节随机值，数据库只存 SHA-256；Web 使用 httpOnly/Secure/SameSite=Lax cookie，Mobile 使用 SecureStore + Bearer。
3. 会话绝对 30 天、空闲 7 天；支持查看和撤销会话；修改/重置密码撤销全部会话。
4. Cookie 写操作使用 Origin 校验 + 双提交 CSRF token；Bearer 不使用 CSRF，但限制 CORS。
5. 邮箱验证和密码找回使用单次、短有效期、哈希存储的 token。
6. 校园认证与注册分离，状态独立记录；邮箱域名只作信号，不自动等于官方认证。
7. 开发身份仅在 `APP_ENV=development` 且 `AUTH_DEV_MODE=true` 时启用，生产禁用。
8. 组织角色为 owner/admin/member；默认只有 owner/admin 能代表组织接受引荐，member 需要 `can_represent`。

## 备选方案

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| Clerk | 接入快、托管安全 | 国内访问、数据位置、合规和成本不确定 | 不采用 |
| Auth.js + 自建表 | 生态成熟 | 仍需自建会话/密码/撤销，抽象层增加复杂度 | 不采用 |
| Keycloak | 功能完整 | 运维重，首版过度 | 不采用 |
| 仅开发假身份 | 最快 | 无法满足 M2 验收，生产不可用 | 不采用 |

## 后果

- 需要自行承担密码安全、限流、会话撤销、邮件发送和账号恢复。
- 需要 `credentials`、`sessions`、验证 token 表和相应 RLS/安全定义函数。
- 首版不支持社交登录、多因素认证和 SSO；后续按试点需求评估。
- 邮件服务供应商待定；开发环境使用邮件捕获。

## 验证

- [ ] 注册、登录、登出、找回、邮箱验证全流程。
- [ ] 会话撤销后旧 token 立即失效。
- [ ] 修改密码撤销其他会话。
- [ ] CSRF/CORS 负向测试。
- [ ] 开发身份在生产构建不可用。
- [ ] 校园认证状态不被注册动作自动提升。
