# AVEN 设计系统

版本：1.2 · 日期：2026-11-11 · 状态：M1-01 令牌已实现；完整设计评审与高保真未完成
需求来源：[原始产品与工程规格](../../Origin%20Plan.md) 第 1–4 节
产品契约：[PRD](../product/PRD.md)

本文把原规格的视觉方向提取为可实现的令牌、布局、组件和验收规则。关键页面另遵循 [核心旅程界面契约](CORE_JOURNEY.md)。新增可复用模式或改变现有语义时同步更新规范；普通页面组合不要求先扩写组件大全。本文不是高保真设计或功能完成证据。

## 1. 定位与原则

### 欢迎入口与无闪烁复核（2026-11-13，后续用户修订）

用户进一步指定 Grok Bot 欢迎页截图，要求重做登录入口并修复持续闪烁。本轮优先采用完整欢迎页：深色纯色画布、静态彩色 AVEN 圆形角色分布在外围、居中品牌与一句介绍、底部单个“登录或注册”动作；点击后打开聚焦的认证面板，手机为底部面板，桌面为居中面板。复用现有正圆 SVG 资产的颜色变体，不复制第三方角色或品牌；无阴影、渐变、漂浮/闪烁动画。

匿名页首次会话检查、focus/pageshow/visibilitychange 不卸载认证树、不清空输入；重复检查共享在途请求。已登录私人视图在隐藏、离线、跨标签页会话变化时遮挡，重新验证后恢复；过期依旧清空。密码恢复链接只把一次性令牌置于 URL fragment，客户端取出即清除，不放查询参数或日志。

### 认证界面参考修订（2026-11-13，用户指定）

本轮用户提供深色 Grok Bot 手机界面与圆形角色图片，要求注册页沿用其比例、留白与 UI 特征，移除光影。该明确指令替代 v0.4 对个人 Web 认证入口的浅色默认；范围为登录、注册、密码恢复与会话检查，不整体改写组织或工程主题。

- 纯色 `#131313` 画布，白色正圆角色与黑色胶囊眼睛；复用已有角色 SVG，用颜色反转适配深色，去掉外层白底圈、阴影与光晕，不复制第三方品牌或设备状态栏。
- 手机内容左右至少 24px；表单最大 360px，角色实际圆形约 88px，标题 28px，正文 14–16px；角色、标题、表单与切换操作分别留白。短屏允许滚动，不能遮挡主操作。
- 52–54px 高的胶囊输入与主按钮，中性灰输入表面、细实线边框；白色主要动作、文字型次要动作；不使用渐变、模糊、阴影或发光焦点。
- 登录、注册、恢复共用认证容器。字段保留可访问标签、自动填充、密码可见切换、输入校验与真实接口行为；主屏只显示简短 Mock 标识，不常驻工程诊断入口。


### 圆形角色动效稿（2026-11-12，待评审）

用户要求角色没有手脚，外轮廓为标准正圆。设计资产见 [角色动效](prototypes/mascot-motion/README.md)：黑色圆形与两只白色胶囊眼睛，主体仅允许平移、旋转、等比缩放，不使用非等比压缩或拉长；眨眼、眯眼、视线偏移发生在眼睛层。无嘴、手脚、阴影、光晕或渐变。

默认轻微运动，可暂停；轮播须主动开启。遵循系统减少动态，保留表情但停掉循环眨眼、位移、缩放、跟随与轮播。当前仅为设计原型和独立 SVG，不能用表情替代真实 Agent 状态或任务完成证据，正式接入仍遵守页面设计门。

### v0.4 图片对齐方向（2026-11-12，待评审）

用户提供两张手机聊天/邮箱连接器截图，要求整体与连接器 UI 尽量一比一对齐。新稿以 Gmail 图为主要视觉基准、Outlook 图为卡片变体，优先于下方 v0.3 的黑色默认画布与开放式助手正文方案。仅更新设计原型，不变更产品令牌或解除 M1-07 评审门。

- 默认浅色：近白画布、暖中性浅灰助手气泡、黑色用户气泡，深色作为同结构适配；正文 16–17px、行高约 1.5，消息间隔 10–14px，左右边距 16px。
- 气泡 26px、连接器卡片 28px，主要按钮、图标按钮与输入框使用胶囊/圆形；SVG 统一圆头、圆连接，矩形图标内部也使用柔和圆角，图标笔画更清晰。
- 连接器卡片按“官方图标—服务名/用途—授权按钮”横向布局，Outlook 支持灰色堆叠变体。大段解释留在相邻消息，不塞进卡片；不复制参考图的验证徽章、个人账号或设备状态栏。
- 手机输入区改为紧凑单行胶囊，多行时自然增长；能力入口与语音/发送按钮靠两端，不常驻第二层工具栏。插件选择、明确授权、失败恢复、草稿隔离与当前用途语义保留。
- 真实服务不因卡片而接通：授权按钮先打开范围确认，确认后只模拟连接状态，不向外部平台请求，不自动读取或发送邮件。样例状态在界面中明确标识。

### v0.3 会话与 Socrates 视觉方向（2026-11-12）

最新视觉约束（用户明确指定）：精致圆角、无光影、干净。v0.3 输入区使用 26px 圆角、连接卡/浮层 20px、按钮与菜单行 12px、标签 8px；头像保持圆形。所有状态不使用阴影、光晕、渐变和背景模糊，表面仅用中性背景与细边框分层；键盘焦点用清晰实线描边，不以发光表达。该约束优先于下方旧版阴影建议。

用户明确要求聊天为主、社交连接与业务能力以插件/小组件按需呈现，取代 v0.2 的业务页面导航。参考本机 Socrates 的 `frontend/src/styles/themes.css`、`parity/{sidebar,topbar,composer-unified}.css`、`packages/ui/src/composer/ComposerFrame.tsx` 与实际聊天截图。复用 Geist Sans / Noto Sans SC 字体方向、黑色聊天画布、`#1A1A1A` 侧栏、`#292929` 抬升表面、`#EDEDED` 正文、`#A1A1A1` 辅助字色，以及 260px 侧栏、52px 顶栏、24px 输入区与轻量工具状态行。手机使用抽屉与底部输入区，取消业务底栏。

推荐人物、邀请、共享预览与对方响应只在相关会话中出现。能力菜单借鉴 Socrates 的分组工具列表和已选插件 Chip；复杂信息按需展开，普通 AI 正文不包成业务卡片。所有关键写操作仍须明确确认，不能把“启用插件”视为同意向另一人共享资料。当前仅更新设计原型，不耦合 Socrates 运行时代码，不修改其项目，也不提前更改生产令牌。

### v0.2 评审主题（2026-11-12）

用户指定参考 ChatGPT 深色界面。M1-07 v0.2 原型采用独立评审主题：页面近黑 `#0B0B0B`、侧栏 `#111111`、输入/选中表面 `#202020`、浮层 `#282828`、文字 `#F3F3F1`、辅助文字 `#A8A8A8`、装饰分隔 `#303030`；必要控件边界继续使用 `#707781`，品牌强调沿用 `#89A795`。颜色通过原型语义变量集中定义，不写入业务组件。浅色主题保持现有 M1-01 语义方向。

AI 输入区采用 24px 圆角，菜单/对话框采用 18px 圆角；普通列表不强制卡片化。桌面侧栏为 248px；手机以四项底栏和可关闭的次级抽屉组合，头像菜单集中身份、隐私和设置。新增主题与圆角只作为待评审方案，不改写已交付的 M1-01 令牌结论；正式通过后再同步 `packages/design-tokens`。该主题不包含 ChatGPT 品牌、订阅、插件、语音或浏览器外壳的复制。

关键词：Minimal、Refined、Quiet、Intelligent、Editorial、Spatial、Functional。

设计目标不是做一个更漂亮的校园社交软件，而是让用户清楚知道：

- AI 正在做什么。
- 为什么推荐这件事。
- 需要自己确认什么。
- 当前执行到了哪一步。
- 最终产生了什么结果。

### 1.1 必须遵守

- 中性色为主，大量留白，细边框，清晰字体层级，轻量动效。
- 强调色只用于重要状态、选中项和关键操作。
- 用背景、边框和排版建立层级，优先不用阴影。
- 为每页建立适用状态矩阵，覆盖加载、空、错误、成功、禁用和无权限；不适用项写明原因，不机械制造无意义页面。
- 所有核心交互必须真实可用；未实现的功能明确说明。
- Web 与原生共享令牌和语义，不强行共享所有组件。

### 1.2 禁止

- 大量渐变背景、玻璃拟态、大面积彩色卡片。
- 每个功能一个独立彩色图标。
- 用 Emoji 代替图标。
- 把所有内容放进带边框的容器。
- 传统 SaaS Dashboard 式的指标卡片堆砌。
- 把 AI 对话做成客服聊天窗口。
- 让工具执行信息占据整个屏幕。
- 用静态成功数据伪装业务功能。
- 没有解释的匹配分数或“AI 认为你们很合适”。

#### 使用规则

- 强调色只用于：选中项、关键操作、品牌标识、少量状态提示。

- 不允许在组件中直接写十六进制颜色；必须引用令牌。
- 深色模式不是简单反色；表面层级和边框对比需单独验证。

### 2.2 字体

| 用途 | 字体栈 |
|---|---|
| 英文/界面 | `Inter, Geist, ui-sans-serif, system-ui, sans-serif` |
| 中文 | `"PingFang SC", "Noto Sans SC", "Microsoft YaHei", sans-serif` |
| 等宽 | `"Geist Mono", ui-monospace, SFMono-Regular, monospace` |

字体大小与行高：

| Token | 大小 | 行高 | 字重 | 用途 |
|---|---:|---:|---:|---|
| `display` | 36px | 1.2 | 600 | 特殊欢迎标题 |
| `h1` | 28px | 1.25 | 600 | 页面主标题 |
| `h2` | 22px | 1.3 | 600 | 页面分区标题 |
| `h3` | 18px | 1.35 | 500 | 卡片/区块标题 |
| `body` | 15px | 1.65 | 400 | 正文 |
| `body-sm` | 14px | 1.6 | 400 | 辅助正文 |
| `caption` | 12px | 1.5 | 400 | 元数据 |
| `micro` | 11px | 1.4 | 400 | 极少量辅助信息 |

行高、字重、字距与断点令牌：

| 类别 | Token | 值 |
|---|---|---|
| 行高 | `lineHeight.display` / `h1` / `h2` / `h3` | 1.2 / 1.25 / 1.3 / 1.35 |
| 行高 | `lineHeight.body` / `body-sm` / `caption` / `micro` | 1.65 / 1.6 / 1.5 / 1.4 |
| 字重 | `fontWeight.regular` / `medium` / `semibold` | 400 / 500 / 600 |
| 字距 | `letterSpacing.tight` / `normal` / `brand` | -0.01em / 0 / 0.12em |
| 断点 | `breakpoint.sm` / `md` / `lg` / `xl` | 640 / 768 / 1024 / 1280 px |
| 字体 | `fontFamily.sans` / `mono` | 界面/中文回退；等宽标识符 |

`lineHeight` 与 `fontSize` 的键一一对应；Web 使用 CSS 变量，原生使用数值乘法。字体栈不依赖未验证的海外字体 CDN。

规则：

- 正文行高 1.65；标题行高 1.25–1.35。
- 不要所有文字都加粗；强调优先用字重 500，标题才用 600。
- 中文正文不小于 14px；移动端正文基线 16，使用平台逻辑单位并支持系统字体缩放，不能固定高度裁字。
- 普通数字与时间沿用界面字体；对齐表格使用 tabular numerals，代码/标识符才使用等宽字体。
- 英文长文本约 68–76ch，中文以实际字形检查行长，不能把 CSS ch 当成汉字数；AI 正文最大 760px。
- Web 长文本使用 rem；原生使用可缩放的逻辑尺寸。字体本地化或自托管，不能依赖校园网络未验证的海外字体 CDN；验证 Android 与 Windows 的中文回退。

### 2.3 间距

基础单位 4px。核心间距：

`4 / 8 / 12 / 16 / 20 / 24 / 32 / 40 / 48 / 64`

| 场景 | 建议 |
|---|---|
| 图标与文字 | 8px |
| 表单字段之间 | 16px |
| 卡片内边距 | 16–20px |
| 区块之间 | 24–32px |
| 页面主区块之间 | 40–48px |
| 桌面页面左右留白 | 32–40px |
| 移动页面左右留白 | 16–20px |

主要内容区必须有充足留白；不要为了展示更多信息把页面挤满。

### 2.4 圆角

| Token | 半径 | 用途 |
|---|---:|---|
| `radius-sm` | 6px | 小型元素、标签 |
| `radius-md` | 10px | 按钮、输入框 |
| `radius-lg` | 14px | 卡片 |
| `radius-xl` | 18px | 大型内容容器 |
| `radius-full` | 999px | 头像、胶囊标签 |

避免所有组件都使用特别大的圆角；同一页面圆角层级不超过三种。

### 2.5 阴影

默认不使用阴影。优先用背景色和 1px 边框区分层级。

只在 Popover、Dialog 和浮动菜单使用轻微阴影：

| 场景 | Light | Dark |
|---|---|---|
| Popover | `0 8px 24px rgba(17,18,20,0.08)` | `0 8px 24px rgba(0,0,0,0.40)` |
| Dialog | `0 16px 48px rgba(17,18,20,0.12)` | `0 16px 48px rgba(0,0,0,0.56)` |

### 2.6 动效

| 动作 | 时长 |
|---|---:|
| Hover | 120ms |
| Button Feedback | 120ms |
| Popover | 150ms |
| Modal | 180ms |
| Sidebar | 200ms |
| Page Transition | 200ms |
| Large Panel | 240ms |

- 缓动默认 `cubic-bezier(0.2, 0, 0, 1)`。
- 动效应自然、克制；不要让整个界面不断运动。
- AI 生成内容平滑流式显示；工具执行使用简洁状态变化，不用复杂加载动画。
- 必须支持 `prefers-reduced-motion`；减少动态时保留状态变化但去掉位移和缩放。M1-01 在生成的 `tokens.css` 中把所有 `--aven-duration-*` 置为 `0ms`，并设置 `scroll-behavior: auto`；组件不得用动画表达唯一状态信息。

### 2.7 图标

使用 Lucide Icons，不混用其他图标库。

| 尺寸 | 用途 |
|---|---|
| 16px | 小型辅助、行内 |
| 20px | 常规 |
| 24px | 重点操作、空状态 |

- 线性图标，视觉线宽 1.5px 或 1.75px。
- 图标颜色继承文字色，不单独上色。
- 菜单项前不放不同颜色的图标。
- 不使用 Emoji 代替图标。

### 2.8 断点与栅格

| 断点 | 范围 | 布局 |
|---|---|---|
| `mobile` | < 640px | 单列，底部导航，页面内 Stack |
| `tablet` | 640–1023px | 单列或双列，侧栏收起 |
| `desktop` | 1024–1279px | 侧栏 + 主区，按需上下文面板 |
| `wide` | ≥ 1280px | 侧栏 + 主区 + 可选上下文面板 |

- 桌面主内容最大宽度 760–900px。
- AI 对话正文最大 760px，居中。
- 上下文面板建议 320–360px，仅在剩余主区可用时并排；断点不是强制三栏开关，空间不足时改为 Drawer 或详情路由，不能挤出横向滚动。
- 移动端不保留固定侧栏；测试 320、390、768、1024、1440 CSS px，并验证 200% 文字放大，数据表等必要二维内容单独处理。

## 3. 布局

### 3.1 桌面端

三层结构：

1. Navigation Sidebar。
2. Main Workspace。
3. Optional Context Panel。

Sidebar：

- 展开 248px，收起 64px。
- 顶部：AVEN Logo、New Action。
- 主导航按开放能力显示：今日 / 发现 / 空间；日程开放后加入，不以空入口充数。
- 中部：最近对话、最近组织、最近关系空间。
- 底部：My AI、Settings、Profile。
- 必须支持收起；收起后保留图标和可访问名称。

Main Workspace：

- 普通页面最大宽度 760–900px。
- 内容按页面需要调整，不强行居中所有内容。
- 页面标题、说明、主操作形成清晰层级。

Context Panel：

- 仅在需要时出现：机会对应组织、人物共同背景、活动参与者和约束、项目成员和目标。
- 不能所有页面强制三栏。
- 关闭后主区自然扩展，不留下空白占位。

### 3.2 移动端

- 原生优先，不做 Sidebar 缩小版。
- 默认保持对话与底部输入区，次级功能通过抽屉、头像菜单和输入区插件菜单可达；连接与业务结果通过相关会话的小组件呈现，不常驻业务底栏（v0.3 用户修订）。
- 主要页面使用原生 Stack Navigation，支持返回手势。
- 聊天输入框必须处理软键盘、Safe Area 和输入焦点。
- 长内容滚动时保持主要操作可达；避免固定元素遮挡内容。
- Web 触控目标至少 44×44 CSS px；原生 iOS 至少 44×44 pt、Android 至少 48×48 dp，不把视觉图标尺寸等同于点击区域。

### 3.3 AI 对话页

- 正文最大 760px，居中。
- 输入框固定在底部区域，页面滚动时保持可用。
- 消息类型至少支持：文本、机会卡、人物卡、组织卡、项目卡、活动卡、行动预览、工具活动、来源引用、确认对话框。
- 工具执行与文字生成不能共用一个模糊的 loading 状态。
- 工具卡片默认折叠，展示简洁摘要；展开后显示执行详情，但不暴露内部 Prompt、隐藏推理或原始工具参数。

## 4. 组件规范

### 4.1 基础组件

| 组件 | 变体/状态 | 要求 |
|---|---|---|
| Button | primary、secondary、ghost、destructive；sm/md/lg | hover、active、focus-visible、disabled、loading；loading 时保留宽度 |
| IconButton | ghost、secondary | 必须有可访问名称；触控目标 ≥ 44px |
| Input | default、error、disabled、readonly | label、hint、error 关联；不要只用 placeholder 当 label |
| Textarea | default、error、disabled | 支持自动高度但有上限；保留换行 |
| Select | default、error、disabled | 键盘可操作；选项分组清晰 |
| Checkbox/Radio | default、error、disabled | 点击标签可选；错误状态可读 |
| Switch | default、disabled | 状态变化有文字或图标辅助，不只靠颜色 |
| Dialog | default、destructive | 焦点陷阱、Esc 关闭、遮罩点击策略明确、标题/描述关联 |
| Popover/Dropdown | default | 键盘导航、碰撞检测、关闭后焦点回到触发元素 |
| Tabs | default | 键盘左右切换；选中态不只靠颜色 |
| List | default、selected、disabled | 行高足够；分隔线克制；支持键盘 |
| Toast | success、error、info | `aria-live`；不遮挡主要操作；可关闭 |
| Badge | neutral、accent、success、warning、destructive | 只表达状态，不堆砌颜色 |
| Avatar | image、fallback | fallback 使用姓名首字母；不外链不可信图片 |
| Tooltip | default | 不承载关键信息；键盘和触摸可访问 |
| Skeleton | text、block、avatar | 形状接近真实内容；减少动态时用静态占位 |
| EmptyState | default | 说明为什么空、下一步做什么 |
| ErrorState | default、retryable | 明确错误、是否可重试、重试操作 |
| PermissionDenied | default | 说明缺少什么权限、如何申请或返回 |

### 4.2 业务组件

| 组件 | 用途 | 关键规则 |
|---|---|---|
| `AIComposer` | 自然语言输入、附件、快捷操作 | 支持发送、停止、重试；显示上下文范围；不伪造语音能力 |
| `Message` | 文本、卡片、行动预览、来源引用 | 区分用户/AI/系统；流式时保持可读；支持复制 |
| `OpportunitySummary` | 机会摘要 | 展示组织、领域、阶段、截止时间、来源与更新时间；不展示无解释分数 |
| `MatchReason` | 推荐理由 | 每条理由对应可验证证据；只展示获授权信息 |
| `ConsentPreview` | 授权预览 | 明确“将共享/不共享”、接收方、用途、有效期；确认前不可发送 |
| `ToolActivity` | 工具执行状态 | 折叠摘要、展开详情、失败可重试；不暴露内部参数 |
| `SourceReference` | 来源引用 | 可定位到来源类型和时间；不泄露私人正文 |
| `ActionPreview` | 行动预览与确认 | 绑定草稿版本；变化后要求重新预览；一次性确认 |
| `RelationshipHeader` | 关系空间头部 | 成员、建立时间、共同目标、关闭入口 |
| `MemberList` | 组织/关系成员 | 角色、状态、权限；不展示不必要的邮箱 |
| `PrivacySummary` | 我的 AI 隐私页 | 当前可见性、有效授权、已共享内容、撤销入口 |

### 4.3 状态组件

数据页面按状态矩阵实现适用项：

| 状态 | 视觉 | 文案要求 |
|---|---|---|
| Loading | 骨架屏或轻量进度 | 说明正在加载什么，不用全屏 spinner 阻塞 |
| Empty | 空状态图标/说明 + 下一步 | 说明为什么空，提供真实可用的下一步 |
| Error | 错误说明 + 重试 | 区分网络、权限、业务冲突、服务不可用 |
| Success | 内容或确认反馈 | 不夸大，不自动跳转打断 |
| Disabled | 降低对比度 + 原因 | 说明为什么不可用，不用“看起来能点”的按钮 |
| Permission denied | 明确说明 + 返回/申请 | 不泄露无权访问的内容 |

## 5. 页面状态规范

- 每个已实现页面交付 loading、empty、error、success、disabled、permission denied 的适用状态矩阵；不适用需说明，业务状态不能用通用错误代替。
- 未实现页面显示“尚未开放”，不提供伪可用操作。
- 所有按钮必须有真实行为；不允许只有视觉反馈。
- 表单错误定位到字段，并在提交时汇总。
- 长文本、超长标题、空字段、网络断开、会话过期必须有布局和文案。
- 流式网络中断时可保留当前仍有权查看的内容并恢复同一 run；授权撤销、会话失效时移除受限内容，不借“继续”重放写操作。
- 删除、撤销、关闭关系等高风险操作必须二次确认，并说明后果。

## 6. 无障碍

目标：WCAG 2.2 AA。

- 正文对比度 ≥ 4.5:1；大号文字 ≥ 3:1。
- 键盘可完成所有核心操作；焦点顺序与视觉顺序一致。
- 焦点环 2px，颜色使用 `focus-ring`，与背景有足够对比。
- Dialog 焦点陷阱；关闭后焦点回到触发元素。
- 表单 label、hint、error 正确关联；错误用 `aria-describedby`。
- 图标按钮有 `aria-label`；装饰图标 `aria-hidden`。
- 流式状态摘要使用 `aria-live="polite"`，按完成段落/关键状态节流播报，不把整个不断变化的对话正文作为逐 token live region。
- 不只靠颜色传达状态；配合文字、图标或形状。
- 支持 `prefers-reduced-motion`。
- 触控区域按第 3.2 节的平台单位执行；考虑 Safe Area、200% 文字放大、320 CSS px 回流和原生系统字体设置。
- 视频/音频（后续）提供字幕或文字替代。

## 7. 内容与语气

- 简洁、平静、具体；避免营销腔和夸张承诺。
- 推荐理由写“使用了哪些信息、为什么相关”，不写“AI 觉得你们很配”。
- 错误文案说明发生了什么、用户能做什么；不暴露内部堆栈、密钥或私人上下文。
- 授权文案必须明确接收方、用途、范围和有效期。
- 不用“无限”“永久”“保证”等无法兑现的词。
- 中文标点统一；中英文之间保留空格；专有名词大小写一致。

## 8. 实现映射

| 层 | 方案 | 约束 |
|---|---|---|
| 令牌 | `packages/design-tokens` | 输出 CSS Variables 与 React Native 令牌；单一来源 |
| Web 样式 | Tailwind CSS 4 `@theme` | 只引用令牌；不写散落颜色 |
| Web 组件 | shadcn/ui + Radix | 保留可访问性；按本文调整外观 |
| 图标 | Lucide | 统一尺寸和线宽 |
| Web 动效 | Motion for React | 支持减少动态 |
| 原生动效 | Reanimated | 不在 JS 线程做重布局 |
| 原生组件 | React Native + Expo | 独立实现，不强行复用 Web DOM 组件 |

令牌命名建议：

```text
--aven-color-background
--aven-color-foreground
--aven-color-accent
--aven-space-4
--aven-radius-md
--aven-font-body
--aven-duration-fast
```

M1-01 负责把本文令牌落到 `packages/design-tokens`，并用对比度工具验证浅色/深色两套值。令牌分为基础值与语义用途；Web/CSS 和原生输出保持同源，不能把 px、pt、dp 当成相同物理尺寸。M1-07 按核心旅程交付双端高保真与可点击原型，再进入对应 UI 实现；所有完成证据单独记录。

## 9. Do / Don't

| Do | Don't |
|---|---|
| 用留白和排版建立层级 | 用大量彩色卡片和阴影堆叠 |
| 用细边框区分表面 | 用玻璃拟态和渐变装饰 |
| 强调色只用于关键状态 | 每个模块一个主题色 |
| 推荐理由对应真实证据 | 展示无解释的匹配分数 |
| 明确展示 AI 执行状态 | 所有状态都显示“AI 正在思考” |
| 未实现功能明确说明 | 提供看起来能点的假按钮 |
| 移动端重新设计交互 | 把桌面 Sidebar 塞进手机 |
| 尊重减少动态设置 | 全屏持续动画 |

### WEB-01 限定实现补充（2026-11-12）

依 ADR-017 新增语义圆角 `bubble: 26px`、`card: 28px`、`composer: 32px`，保留已有令牌以免影响工程/组织界面。个人 Web 采用本地 Geist 与 Noto Sans SC 分片，随附 OFL 许可；不会请求第三方字体。基础 SVG 操作图标使用 v0.4 的 Lucide 资产（ISC），圆头/圆连接，停止按钮内部矩形 `rx=4`。角色主体始终正圆、无手脚，仅等比缩放；动画资源与低动态规则沿用已验资产。首批聊天/表单/按需连接及通知面板不等于全部 v0.4 小组件实现或正式双端设计验收。

### 聊天应用工作区修订（2026-11-13，用户最新截图）

用户要求按 Grok Bot 聊天/分页截图及 Socrates UI 重新开发个人工作区。该方向替代个人聊天的浅色默认；欢迎与认证保持已有实现。工作区采用纯黑 `#080808`、中性表面 `#222222`、前景 `#eeeeee` 与次要文字 `#999999`，无阴影、渐变或循环角色动画。消息与输入共用最大 720px 阅读宽度，正文 16px/26px，手机边距 16px，气泡 24px，控件至少 44px。用户消息靠右，助手内容靠左；完成后不反复显示状态角色，错误、停止和恢复保持明确。

桌面左侧导航，手机底部五入口：对话、记忆、连接、通知、更多。辅助页面在主内容区展示，不将所有功能堆为浮层。更多包含对话记录、连接器、账号与安全入口；不伪造尚无后端的资讯、目标追踪或文件库。输入框只保留加号、消息和发送/停止；加号打开连接器。输入支持中文组合、换行、自适应高度；上翻阅读时不自动抢滚动，切换导航保留当前会话。新对话仅在无待确认请求时清空当前视图，不等于删除服务端历史。

回复支持安全的段落、列表、强调和代码块展示与复制；不执行回复中的 HTML。模拟模式保持显式标识；可改善确定性示例的可读性与意图分支，但不把模板称为真实模型，也不启用第三方授权。状态覆盖初始、空、生成、完成、停止、断流恢复、未知提交与会话暂停；私人视图暂停时隐藏并复核来源，不因导航或缓存绕过权限。
