## 1. 范围与设计验收

2026-11-12 实施授权：用户明确要求开始下一阶段，按 [ADR-017](../architecture/decisions/0017-personal-web-increment.md) 允许个人 Web 限定主线先行编码；M1-07 整体仍待正式双端评审。v0.4 与正圆角色作为本轮视觉基线，未覆盖页面继续受原设计门约束。

2026-11-13 Halo 修订（WEB-04，待评审）：用户提供 6 张 Grok Bot 截图并要求个人 Web 尽量模仿其界面与功能。按 [ADR-018](../architecture/decisions/0018-personal-web-halo-ui.md)，个人 Web 采用近黑主题与“首页 → Bot 资料页 / 对话页”屏幕栈，记忆、连接、通知与账号为底部 Sheet，连接器在“连接应用”Sheet 与对话内授权卡片中按需出现；授权、用途预览、双方决定与撤销边界不变，授权卡片只做本页 Mock。截图与偏差见 [WEB-04](../development/WEB_04.md)。

2026-11-12 v0.4 图片对齐修订：用户要求以提供的两张手机聊天/邮箱卡片截图作为当前视觉依据，整体和连接器尽量一比一对齐。当前稿默认浅色，助手正文改为浅灰圆角气泡，用户消息为黑色胶囊气泡；输入区单行胶囊，连接器采用 Gmail 横向白卡与 Outlook 灰底堆叠变体。压缩消息间距、统一 SVG 圆头/圆连接及内部圆角。布局与外观以此修订优先，产品的对话优先、独立用途授权、模拟标识和正式设计评审门不变。不得把参考图的第三方品牌、验证状态或账号内容当作 AVEN 已具备的能力。

2026-11-12 用户修订（v0.3，优先于下方 v0.2 的导航方案）：AVEN 的核心是具有社交与跨终端连接能力的 AI 对话。新对话和最近会话构成主要界面；不再把“今日/发现/空间/我的 AI”四入口、引荐和机会管理作为产品首层。发现人、连接邀请、机会、协作等通过输入框插件菜单与对话内小组件按需出现；用户可在当前对话检查共享内容、确认或跳过建议，接收方终端独立决定。引荐是可调用能力，不是主页面任务。视觉直接复用本机 Socrates 成熟聊天界面的字体、配色、间距、输入区和工具菜单模式，仍使用 AVEN 品牌与权限语义。

v0.3 可点击稿保存在 `prototypes/m1-07-v3/`。个人数据用途、授权预览、双方决定、撤销边界不变；承载方式改为会话小组件与按需详情。跨终端、插件、小组件状态均须标明设计模拟，不声明新的后端能力已实现。v0.2 保留为被用户否定的页面导向探索，不作为推荐实现方案。正式双端评审仍待完成。

v0.3.1 交互细化：输入草稿仅保留于当前页面内存，按模拟终端隔离；选择插件或上下文不清空草稿。空白、离线时禁止发送；恢复连接不自动重放，回复失败的重试不重复提交用户消息或执行高影响行动。读者主动向上阅读时保留位置，并提供回到最新入口。按需侧面板作为模态对话框处理：隔离背景、循环焦点、Escape 关闭并恢复触发位置；工具菜单支持方向键、Home/End 与 Escape。以上仅为原型交互，须在产品实现后另做业务 E2E 与设备验证。

2026-11-12 视觉修订方向（v0.2，待正式评审）：依据用户提供的 ChatGPT 深色界面截图，增加以留白、低对比表面、线性图标、圆角输入框和头像菜单为主的设计稿。双端主入口统一为“今日、发现、空间、我的 AI”，引荐与隐私从侧栏/头像菜单及关联任务到达；手机抽屉承载次级功能，保留四项主导航。设置采用桌面分栏、手机列表到详情。所有内容仍是明确标识的样例，真实模型、语音、上传和消息发送不因设计演示而视为实现。

v0.2 原型独立保存于 `prototypes/m1-07-v2/`，不覆盖 v0.1，也不进入 `apps/web` / `apps/mobile` 产品编码。视觉主题与输入框形态变更见设计系统“v0.2 评审主题”；正式评审通过前不修改 M1-01 已交付令牌。

首轮只设计个人发现与引荐、组织处理、关系与隐私，不先铺齐 Life、Analytics 等入口。参考成熟 AI 产品的信息组织，不复制其整套页面；AVEN 的辨识度来自“推荐证据 → 共享边界 → 真实行动”的连续表达。

进入对应 UI 实现前，M1-07 必须交付：

- 可复查的高保真稿与可点击原型，附文件路径或评审链接、版本和评审结论；覆盖下表的桌面与手机路径，不以本文的文字描述代替。
- 统一的中文信息层级：页面标题、当前对象、状态、一个主要操作；组织管理可采用更紧凑的列表密度，不强行套用对话正文宽度。
- 真实长度的脱敏中文内容、浅深色样例、关键错误/过期/撤销状态；样例和设计原型明确标识，不能计入功能验收。
- 每页状态矩阵：loading、empty、error、success、disabled、permission denied，逐项标注适用/不适用及原因，另列业务状态。
- 字体回退、长标题、200% 文字放大、键盘、焦点与固定操作区域的检查记录；实际设备验证仍须在实现后完成。

## 2. 导航与身份

- 中文界面以“新对话、最近会话”为主，手机使用抽屉与底部输入区，不常驻“今日、发现、空间、我的 AI”业务底栏。连接与机会等按需进入对话；插件目录和已建立连接为次级入口，不把尚未开放页面常驻导航。
- 桌面可见当前个人/组织身份，组织控制台有明确组织名称与切换器。个人记忆不可因切换到组织而进入组织上下文。
- 切换身份保留合理的返回路径，但清除旧组织查询、选择与草稿执行权限；页面标题、确认按钮和预览均显示本次操作主体。
- 详情使用可分享的规范路由；桌面允许侧面板预览，手机使用完整 Stack 页面。刷新、深链、返回后都能恢复对象，不依赖临时弹窗状态。
- 首次浏览公开机会不要求先完成长对话。需要认证或资料时在相关动作处渐进说明，避免首屏强制填写全部履历。

## 3. 页面契约

v0.3 中，下表描述功能信息覆盖，不要求每项成为一级页面。机会详情、授权预览、引荐决定与关系上下文可在会话小组件及按需详情中承载；复杂/高影响确认仍须完整显示接收方、实际值、用途、期限与影响。对话优先并不免除这些契约。

| 页面 | 首要问题与信息顺序 | 主操作 | 桌面 / 手机映射 |
|---|---|---|---|
| 今日 | 我需要处理什么？待办 → 有依据的机会 → 可选 AI 输入 | 处理最高优先级待办；无待办时发现机会 | 不堆指标卡；手机优先显示待办与下一步，不强制展示空日程 |
| 机会发现 | 哪些机会值得看？查询/筛选 → 标题与组织 → 要求/截止 → 推荐依据 | 查看机会 | 桌面紧凑结果列表，可选预览面板；手机列表到完整详情，筛选用 Sheet |
| 机会详情 | 这是真实且适合我的机会吗？组织与认证 → 内容/要求 → 时间投入/截止 → 依据/来源 | 申请引荐 | 组织补充信息放可选侧栏；手机底部主操作不遮挡最后一段正文 |
| 授权预览 | 谁会看到什么？接收组织/代表范围 → 用途 → 共享字段实际值 → 不共享项 → 期限 | 确认并发送 | 桌面独立页面或足够宽的 Dialog；手机完整页面，不能挤成窄小确认弹窗 |
| 我的引荐 | 现在到哪一步？机会 → 状态/时间 → 对方响应 → 可用操作 | 查看进展或补充资料 | 状态时间线相同；撤回、过期与再次申请明确区分 |
| 组织收件箱 | 哪项请求需要决定？组织身份 → 待处理列表 → 请求详情/获授权资料 → 决定 | 接受并建立关系 | 桌面主从列表；手机列表到详情；拒绝、补充资料为次级操作 |
| 关系空间 | 已经建立什么联系？参与者/状态 → 共同目标 → 下一步 → 会话/共享上下文 | 开始交流或执行明确下一步 | 手机不一次铺开全部分区；共享上下文有独立入口、来源与到期状态 |
| 隐私与授权 | 什么正在被使用和共享？处理用途 → 有效授权 → 接收方/字段/期限 → 历史 | 查看并撤销指定授权 | 双端都可检查实际快照；撤销一个授权不误导为撤销全部共享 |

### 3.1 机会与推荐

- 推荐理由使用可核对的短句，例如“你允许匹配的机器人项目经历，与该机会的控制系统要求相关”。本人可以检查证据；组织只看其获授权快照，不沿证据跳转到私人记忆。
- 明确区分“基于已确认资料推荐”“按搜索条件找到”和“没有足够资料判断”；没有证据就不显示个性化理由。
- 状态包括无结果、筛选过严、资料不足、机会关闭/到期和认证不足；每个状态有真实下一步。
- 截止时间显示时区与实际日期；不只显示容易失真的“还剩两天”。长标题允许换行，领域标签不得挤走核心操作。

### 3.2 授权预览

- 展示字段的实际快照值，不只写“共享个人资料”。联系人、邮箱等敏感字段不能藏在合并标签内。
- 引荐用途与关系用途分别确认、分别显示字段和期限。关系用途默认不勾选；仅确认引荐也可发送，接受后关系空间的共享上下文为空。
- 显示“组织中当前有代表权限的成员可读”，不误导为仅当前管理员一人；接收范围不清楚时禁止发送。
- 显示数据不会包含的内容；不以“私人记忆不共享”的笼统承诺掩盖用户本次明确选中的记忆字段。
- 服务端预览凭据绑定 actor、接收方、字段值/来源版本、用途、期限与失效时间。字段、接收方、用途或来源发生变化时必须重新预览。
- 网络超时后先用同一幂等键查询/重试发送结果，显示“正在确认发送结果”，不直接提示重新发送新请求。

### 3.3 收件箱、决定与关系

- 未发送的候选不出现在组织收件箱。有效引荐的元数据和私人资料分开加载与鉴权；撤销后可保留必要状态，但原资料不能闪现。
- 接受动作说明将建立关系空间；重复点击或并发处理返回同一关系。内容版本已变化时提示重新阅读，不静默执行旧决定。
- 已被其他代表处理、机会关闭、人数已满、授权失效分别说明；敏感错误不透露无权知晓的主体。
- 没有关系用途授权时显示“尚未共享资料”，而不是伪造共同背景。授权到期/撤销时以状态占位替换内容，不只在 Toast 中提示。
- 关闭关系不等于删除全部历史，也不等于撤销所有独立授权；操作前分别说明并提供相关隐私入口。

### 3.4 撤销与恢复

- 撤销确认列出此授权涉及的接收方、用途、字段和空间；说明其他独立授权可能仍然有效。
- 成功文案：“此授权已撤销，系统将拒绝新的授权读取；已送达内容或系统外副本无法收回。”不承诺删除对方截图或截断已发出的网络字节。
- 当前客户端立即移除可控快照缓存；其他设备在下一次读取、页面恢复和流式复核时重新验证。离线时不显示缓存的受授权私人内容。
- 会话失效先清除私人视图，再引导重新登录；重登不得自动重放发送、接受或确认行动。

## 4. AI 与移动端体验

- AI 输入支持中文输入法组合态，未结束输入组合时 Enter 不误发送；支持停止、失败恢复与明确的上下文选择。
- 用户主动向上阅读时不强制滚到底；新内容提供“有新内容”入口。文本增量不逐 token 触发整段屏幕阅读播报。
- 断开订阅与取消任务不同：离开页面不承诺撤销已执行动作；取消结果明确哪些动作尚未执行、哪些已提交。
- Android 返回键先关闭输入法/Sheet，再按导航栈返回；重进页面和 App 从后台恢复要复核会话与授权。
- 不把 Expo Go 截图作为 development build 或发布包验收。M5 使用 development build，M7 使用实际安装包验证弱网、深链、字体缩放和系统权限。
