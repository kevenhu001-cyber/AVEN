全局规范、错误码、SSE 和首条闭环路径见 [TDD 第 11 节](../architecture/TDD.md#11-api-契约)。本目录用于记录每个端点的完整契约，避免实现与文档漂移。

## 编写模板

每个端点至少包含：

```text
### POST /api/v1/example

- 认证：Cookie / Bearer
- 权限：所需角色、资源/字段级检查、组织上下文、授权用途/对象/来源
- 幂等：Idempotency-Key、请求哈希、并发占位、重放鉴权与结果未知时的恢复
- 请求：Zod Schema 名称、字段、示例
- 成功：状态码、响应 Schema、示例
- 失败：错误码、HTTP 状态、可重试性
- 副作用：数据库写入、锁顺序、Outbox 事件、审计；事务内无外部调用
- 缓存：缓存策略、客户端失效、私人/授权正文是否禁止持久化
- 版本：引入版本、乐观锁/内容版本、兼容策略
- 验收：成功、越权、撤销/过期、并发、重试与取消的实际断言
```

## 规则

- 产品语义由 PRD/TDD/SCHEMA 与本文约束；`packages/contracts` 的 Zod Schema 是唯一可执行请求/响应来源，可生成 OpenAPI 与客户端类型。发现冲突先澄清契约，再在同一变更修正文档、Schema 和测试，不能用当前代码反向覆盖安全要求。
- 所有写操作必须说明权限、事务边界、幂等和审计。
- 列表使用 cursor 分页；不使用 offset。
- 错误使用统一结构：`{ error: { code, message, request_id, retryable, details? } }`。
- 密码/哈希、密钥和原始 token 不进入日志、分析或错误。仅专用认证响应可安全交付本次凭据，不能被通用幂等缓存保存；本人/有效授权接口可返回必要私人正文，其余响应不得夹带。
- 私人数据与授权快照使用 private, no-store；幂等重放、SSE 恢复、序列化和客户端重用均重新鉴权。未授权资源存在性按 404 处理，不用可枚举错误透露它。
- cursor 使用稳定排序（时间 + 唯一 ID），绑定查询范围；跨用户/组织游标不可直接复用。
- 破坏性变更升 API 版本；新增可选字段保持向后兼容。
- 端点文档与实现同一可审查变更交付（提交或 PR）；未实现端点不写成可用。1.1 在发布前以 /referrals 分离引荐，Agent 改为 POST 创建 + GET 事件，不保留未发布旧路径的伪兼容层。

## 首批端点

按首条闭环顺序补充：

1. 认证与会话：注册、登录、登出、邮箱验证、密码找回、会话列表/撤销。
2. 本人、校园与组织：`/me`、校园成员、组织、成员、邀请。
3. 个人上下文：记忆、来源、需求。
4. 组织机会：创建、编辑、发布、暂停、关闭。
5. 匹配与引荐：/matches 只返回本人候选；/referrals 发送、补充、独立决定、撤回。
6. 授权：服务端预览、创建、查询、撤销；关系用途单独确认。
7. 关系空间：列表、详情、共享上下文、关闭。
8. 异步与 Agent：任务查询、POST turns 创建 run、GET runs/:id/events 订阅/恢复、行动确认/取消。

端点级文档完成前，以 [TDD](../architecture/TDD.md) 和 [SCHEMA](../database/SCHEMA.md) 为契约基线。
