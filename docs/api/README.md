# API 契约文档

状态：M0-01 仅锁定路径、错误码和权限语义；端点级请求/响应随实现补充。

全局规范、错误码、SSE 和首条闭环路径见 [TDD 第 11 节](../architecture/TDD.md#11-api-契约)。本目录用于记录每个端点的完整契约，避免实现与文档漂移。

## 编写模板

每个端点至少包含：

```text
### POST /api/v1/example

- 认证：Cookie / Bearer
- 权限：所需角色与资源级检查
- 幂等：是否需要 Idempotency-Key
- 请求：Zod Schema 名称、字段、示例
- 成功：状态码、响应 Schema、示例
- 失败：错误码、HTTP 状态、可重试性
- 副作用：数据库写入、Outbox 事件、审计
- 版本：引入版本、兼容策略
```

## 规则

- `packages/contracts` 中的 Zod Schema 是请求/响应的唯一实现来源；文档与 Schema 不一致时以 Schema 为准并修文档。
- 所有写操作必须说明权限、事务边界、幂等和审计。
- 列表使用 cursor 分页；不使用 offset。
- 错误使用统一结构：`{ error: { code, message, request_id, retryable, details? } }`。
- 不记录或返回密钥、密码、token、私人正文和未授权上下文。
- 破坏性变更升 API 版本；新增可选字段保持向后兼容。
- 端点文档与实现同一 PR 交付；未实现的端点不写成可用。

## 首批端点

按首条闭环顺序补充：

1. 认证与会话：注册、登录、登出、邮箱验证、密码找回、会话列表/撤销。
2. 本人、校园与组织：`/me`、校园成员、组织、成员、邀请。
3. 个人上下文：记忆、来源、需求。
4. 组织机会：创建、编辑、发布、暂停、关闭。
5. 匹配与引荐：搜索、候选、决定。
6. 授权：创建、查询、撤销。
7. 关系空间：列表、详情、共享上下文、关闭。
8. 异步与 Agent：任务查询、Agent turns、行动确认/取消。

端点级文档完成前，以 [TDD](../architecture/TDD.md) 和 [SCHEMA](../database/SCHEMA.md) 为契约基线。
