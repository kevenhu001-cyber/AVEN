# AI 会话历史与小组件恢复设计

日期：2026-11-13。状态：待实施设计，不是已开放 API 或数据库迁移。基于本轮用户授权的优化计划；当前个人 Web 仍以页面内存保存聊天与插件结果。

## 范围与现状

现有 `conversations`、`messages`、`agent_runs`、`agent_run_sources` 已保存会话与派生来源；Agent HTTP 层已有创建、run 查询、SSE 和取消，没有会话列表与历史消息分页读取。SSE 事件默认保留 24 小时，不能当作永久消息历史。`ChatExtra` 仅在 React 内存中，不应直接序列化成可绕过授权的历史卡片。

下一包目标：刷新、规范深链与重新登录后，用户可主动恢复本人会话；运行中的回复恢复同一 run，不重建请求或重放副作用。不使用 localStorage、IndexedDB 或 Service Worker 保存私人正文。

## 拟议 HTTP 契约（尚未实现）

- `GET /api/v1/agent/conversations?cursor=...&limit=...`：本人个人会话，按更新时间与 ID 键集分页。首批不混入组织/关系会话；若扩展，另行定义当前代表权与类型过滤。响应只含 ID、类型、时间与活动 run 元数据，不将用户首句自动复制到永久标题。
- `GET /api/v1/agent/conversations/:id/messages?before=...&limit=...`：受保护历史，返回消息 ID、角色、创建时间、当前可读正文或失效占位，以及关联 run ID / 状态 / 可用恢复游标。明确首次倒序分页与客户端升序呈现规则。
- 页面拟采用 `/chat?conversation=<uuid>`；`q` 继续只表示查找。非法 ID 拒绝；跨用户与不存在统一 404。切换时先清除旧会话正文、abort 旧订阅，再加载目标。

分页上限、游标 Schema、统一错误、响应版本及 API 客户端方法须在实现前补入 `docs/api/AGENT.md` 和 `packages/contracts`，不能仅凭本文调用。

## 安全与一致性

1. 元数据、用户消息、助手派生消息分别核对所有权和实时来源依赖。历史消息读取复用运行时来源复核能力；来源失效后只保留最小状态占位，不回传派生正文。
2. 所有读取使用主库和 `private, no-store`。会话失效、离线及页面恢复期间先隐藏正文，重新鉴权后才能恢复。组织/关系消息不因历史成员记录继续授权。
3. 恢复时区分已保存完整消息与未终止增量：完整消息不叠加旧 delta；活动 run 从一致的文本快照和对应 sequence 继续，不能独立保存两者。24 小时事件过期返回明确状态，不重新推理。
4. 取消但已有部分回复的历史保留语义需单独实现和验证。当前 Worker 只在成功时追加完整助手消息，不能承诺取消后刷新仍能恢复全部部分正文。
5. 幂等键只用于原请求结果核对；打开历史、刷新、重新登录均不自动发起创建、发送或行动确认。

## 小组件持久化

建议以带版本的消息部件记录工具调用和业务对象引用，字段包括稳定部件 ID、消息/run 关联、种类、协议版本、调用 ID、业务对象 ID 与顺序。具体表名和索引待现有表/读取需求复核后确定；若新增表，必须新增迁移、最小角色权限与 FORCE RLS，不修改已应用迁移。

私人邮件、共享快照与日历内容不直接当成永久卡片正文。读取引用时复核账号连接、用途授权、来源、版本与期限；授权撤销显示失效占位。历史卡片默认只读，任何确认按钮都要读取当前服务端状态并生成新的有效预览，不能复用历史确认 token。

## 验证与交付门

- 两个账号的会话、消息、小组件隔离；伪造主体与游标不能越权。
- 翻页边界、同一时间排序、刷新、前进/后退、切换时旧请求晚到、并发消息及活动 run 恢复。
- 来源删除/撤销、会话过期、离线恢复、24 小时事件过期、取消部分回复和重复事件。
- 浏览历史不调用 Provider，不重复工具动作；历史正文不播放入场或增量动画。
- 新迁移验证空库/升级、RLS、来源复核与性能；同步 API、共享客户端、导航辅助脚本及手机/桌面 E2E。

真实接口、迁移和页面交付前，本设计保持待实施。插件授权到真实适配器的桥接、远端撤权、工具审计持久化仍是后续独立工作。
